# 섹션 02. 프로젝트를 이해하고 문제 발견하기 (45분)

> 장표 `09·33 ~ 12·33`

## 목표

같은 프로젝트에 **통제된 지시**를 던져 문제 후보를 뽑고, 조별로 **오늘 고칠 문제 하나**를
고른다. 이 섹션에서도 코드를 고치지 않는다.

## 1단계: 구조와 문제점 (15분)

상위 `prompts/`에서 구조 파악과 문제점 분석에 해당하는 프롬프트를 골라 **한 번에**
붙여넣는다. 채팅 1회로 끝낸다.

## 2단계: 존재 확인 (10분)

AI가 말한 파일과 메서드를 **직접 열어서 확인한다.**

| 후보 | AI가 말한 파일·메서드 | 실제로 있는가 | 코드가 AI 설명과 같은가 |
| --- | --- | --- | --- |
| 1 | | | |
| 2 | | | |
| 3 | | | |

없는 파일이나 메서드를 말했다면 그 자리에서 표시한다. 이것도 오늘의 산출물이다.

## 3단계: run 출력과 대조 (5분)

`./scripts/run.sh` 출력을 다시 본다. 코드 해석에 앞서 **AI의 주장과 직접 대조할 수 있는
관찰 결과**를 먼저 확보하는 단계다.

각 후보에 대해 다음을 판정한다.

| 후보 | run 출력에서 눈으로 보이는가 | 어느 줄인가 |
| --- | --- | --- |
| 1 | 보임 / 안 보임 | |
| 2 | 보임 / 안 보임 | |
| 3 | 보임 / 안 보임 | |

`run` 출력에 나타나는 문제는 근거가 확실하다.
나타나지 않는 문제는 섹션 03에서 더 확인해야 한다.

## 4단계: 조별 판단 (15분)

후보마다 셋 중 하나를 고른다.

- **수정한다** — 오늘 고칠 문제 (조당 **하나만**)
- **추가 확인한다** — 근거가 부족해서 지금은 판단 못 함
- **수정하지 않는다** — 문제인 건 알지만 오늘 고치지 않음

| 후보 | 판정 | 근거 | 근거가 된 코드 위치 또는 출력 줄 |
| --- | --- | --- | --- |
| 1 | | | |
| 2 | | | |
| 3 | | | |

### 규칙

- **`수정한다`는 정확히 하나만 고른다**
- **`수정하지 않는다`를 반드시 하나 이상 만든다**
- 판정 근거는 "AI가 그렇게 말해서"가 될 수 없다

> 수정할 문제를 고르는 것보다
> **수정하지 않을 문제를 고르고 그 이유를 말하는 것**이 더 어렵고 더 중요하다.

## 산출물

- 채운 표 3개
- 오늘 고칠 문제 하나와 그 선택 근거
- 거절한 제안 하나 이상과 그 이유
- 조별 발표 1분 분량 (무엇을 고르고 무엇을 버렸는가)
