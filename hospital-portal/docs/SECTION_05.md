# 섹션 05. "완료했습니다"를 검증하기 (50분)

> 장표 `23·33 ~ 27·33`

## 목표

AI의 완료 보고를 **사람이 실행한 출력으로만** 판정한다. 그리고 섹션 01에서 저장한
첫 결과와 지금을 비교한다.

## 1단계: 변경사항 검증 (15분)

상위 `prompts/`에서 변경사항 검증에 해당하는 프롬프트를 사용한다. **사람이 먼저
실행하고 출력을 붙여넣는다.**

```bash
git diff
./scripts/verify.sh
./scripts/run.sh
```

| 완료 조건 | 판정 | 근거가 된 출력 줄 |
| --- | --- | --- |
| | PASS / FAIL / NOT VERIFIED | |

### 규칙

> **붙여넣지 않은 것은 전부 `NOT VERIFIED`다.**
>
> `NOT VERIFIED`가 남아 있으면 완료가 아니다.

AI가 근거 없이 `PASS`를 썼다면 그 자리에서 표시한다.

## 2단계: AI 자기 리뷰와 사람 리뷰 (15분)

상위 `prompts/`에서 자기 리뷰·코드 리뷰에 해당하는 프롬프트를 사용한다.

AI가 고른 "먼저 봐야 할 3줄"을 **사람이 직접 열어서 확인한다.**

| 줄 | AI의 설명 | 사람이 확인한 결과 | 동의하는가 |
| --- | --- | --- | --- |
| 1 | | | |
| 2 | | | |
| 3 | | | |

최종 판정은 사람이 한다.

```text
승인 가능 / 수정 후 승인 / 재작업 필요:
판정 근거:
판정자:
```

## 3단계: 첫 결과와 비교 (20분)

**섹션 01에서 저장한 P1 답변을 다시 연다.** 같은 프로젝트, 같은 문제다.

| 비교 항목 | 섹션 01 (짧은 지시) | 지금 (통제된 절차) |
| --- | --- | --- |
| 문제 후보의 개수 | | |
| 각 주장의 근거 유무 | | |
| 실제로 바뀐 파일 수 | | |
| 검증 결과의 형태 | | |
| 사람이 판단한 지점 | | |
| 완료 조건 | | |
| **되돌려야 했던 변경** | | |
| **다시 해야 할 작업** | | |

### 토론

- 첫 결과는 근거가 있었는가?
- 변경 범위가 더 작아졌는가?
- 검증 결과가 더 명확해졌는가?
- **사람이 판단한 지점이 어디였는가?**
- 첫 결과를 그대로 운영에 반영했다면 무슨 일이 있었을까?

### 생산성 질문

첫 결과는 **몇 초** 만에 나왔고, 지금 결과는 **몇 시간**이 걸렸다.
그런데도 지금 방식이 더 빠르다고 말할 수 있는가?

| | 짧은 지시 | 오늘의 절차 |
| --- | --- | --- |
| 결과가 나오기까지 | 초 단위 | 시간 단위 |
| 되돌린 변경 | | |
| 운영 반영 후 재작업 | | |
| **총 소요** | | |

> **AI로 빨라지는 것은 생성이지 완료가 아니다.**
