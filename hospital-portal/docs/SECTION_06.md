# 섹션 06. 상태를 보존하고 반복 작업을 시스템화하기 (45분)

> 장표 `28·33 ~ 33·33`

## 목표

**오늘 다 못 고친 것을 넘길 수 있는 형태로 만든다.** 그리고 오늘 반복한 지시를 규칙으로
바꾼다.

> 오늘 고친 문제는 하나다. 나머지는 남아 있다.
> **그것을 숨기지 않고 넘기는 것이 이 섹션의 전부다.**

## 1단계: 인수인계 문서 (15분)

`docs/HANDOFF_TEMPLATE.md`를 `HANDOFF.md`로 복사한다.

상위 `prompts/`에서 인수인계에 해당하는 프롬프트로 초안을 받는다. 초안에 다음이 반드시 들어가야 한다.

- 고친 문제 **하나**와 그 근거
- 고치지 않기로 한 문제와 **그 이유**
- 아직 판단하지 못한 문제
- `NOT VERIFIED`로 남은 항목
- 다음 담당자가 먼저 열어야 할 파일

**승인자와 최종 판정은 사람이 적는다.**

## 2단계: 인수인계 검증 (15분)

상위 `prompts/`에서 인수인계 검증에 해당하는 프롬프트를 사용한다. **반드시 새 채팅
창을 연다.**

새 AI가 `HANDOFF.md`만 읽고 답한 내용을 확인한다.

| 질문 | 새 AI의 답 | 맞는가 |
| --- | --- | --- |
| 지금 프로젝트는 어떤 상태인가 | | |
| 다음에 무엇을 해야 하는가 | | |
| 문서만으로 알 수 없는 것은 무엇인가 | | |

> **새 AI가 틀렸다면 AI가 나쁜 것이 아니라 `HANDOFF.md`가 부족한 것이다.**

3번 답변에 나온 항목을 `HANDOFF.md`에 채워 넣는다.

여유가 있으면 **다른 조의 `HANDOFF.md`**를 읽고 같은 질문에 답해 본다.
사람이 읽고 이해하지 못하는 문서는 인수인계 문서가 아니다.

## 3단계: 반복 작업 규칙화 (10분)

상위 `prompts/`에서 반복 작업 규칙화에 해당하는 프롬프트를 사용한다.

오늘 6시간 동안 반복한 지시를 네 가지로 분류한다.

| 분류 | 뜻 | 오늘의 예 |
| --- | --- | --- |
| Prompt | 매번 다시 써야 함 | |
| Project Rule | 항상 적용 (`copilot-instructions.md`) | |
| Automation | 명령 한 줄이면 됨. **AI 불필요** | |
| 불필요 | 한 번만 필요했음 | |

`Automation`으로 분류된 것이 있다면 주목한다.
**AI에게 시킬 필요가 없는 일을 AI에게 시키고 있었다는 뜻이다.**

`Skill`은 Claude Code의 기능이며 Copilot에는 없다. Copilot에서는
`.github/copilot-instructions.md`와 `.github/prompts/*.prompt.md`로 나눠서 만든다.

## 4단계: 최종 산출물 확인 · 마무리 (5분)

```text
[ ] RESULT.md          섹션 01 원본 답변 + 근거 분류 + 최종 판정
[ ] PROGRESS.md        승인자 이름과 Task 상태
[ ] HANDOFF.md         남은 문제와 다음 작업
[ ] git diff           실제 변경
[ ] verify 출력        JUnit + 컴파일 경고
[ ] copilot-instructions.md 초안
```

## 회고

- 처음에는 AI에게 무엇을 맡겼는가?
- 마지막에는 어떤 판단을 사람이 담당했는가?
- 다음 프로젝트에서 반드시 유지할 규칙은 무엇인가?
- **오늘 고치지 않은 문제를 넘길 수 있게 되었는가?**

> AI 개발 생산성은 코드를 많이 생성하는 능력이 아니라,
> AI에게 일을 맡기면서도 **근거·범위·품질·완료 여부를 인간이 통제하는 능력**이다.
