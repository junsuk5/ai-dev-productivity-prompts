# 섹션 04. 인간이 승인하고 작은 단위로 구현하기 (60분)

> 장표 `18·33 ~ 22·33`

## 목표

**사람이 승인한 뒤에만** 코드를 고친다. 오늘 처음으로 코드를 수정하는 섹션이다.
고치는 것은 **문제 하나**뿐이다.

## 1단계: 인간 승인 (10분)

`PROGRESS.md`의 Task를 놓고 판정한다.

- **승인** — 그대로 진행
- **수정 후 승인** — 범위를 줄이거나 완료 조건을 바꾼 뒤 진행
- **보류** — 근거가 부족하므로 진행하지 않음

`PROGRESS.md`에 **승인자 이름**을 적는다. 이름이 없으면 다음 단계로 가지 않는다.

```text
승인자:
승인 일시:
승인 범위:
승인하지 않은 범위:
```

## 2단계: 실패 테스트 먼저 (20분)

상위 `prompts/`에서 구현 지시에 해당하는 프롬프트를 사용한다.

AI가 제시한 것 중 **테스트 코드만 먼저** 적용한다.

```bash
./scripts/verify.sh
```

### 반드시 확인할 것

> **테스트가 실패하는 것을 눈으로 본다.**

실패 메시지를 `PROGRESS.md`에 붙여넣는다.

실패하지 않는다면 둘 중 하나다.

- 테스트가 문제를 재현하지 못하고 있다 → 테스트를 고친다
- 문제가 원래 없었다 → 섹션 03으로 돌아간다

**실패를 보지 않고 수정하면, 그 테스트가 무엇을 지키는지 알 수 없다.**

## 3단계: 최소 수정 (15분)

이제 수정 코드를 적용한다.

```bash
./scripts/verify.sh
```

### 규칙

- 승인된 파일 외에는 열지 않는다
- 이름 변경, 포맷 변경, 정리를 같이 하지 않는다
- 새 라이브러리를 추가하지 않는다
- AI가 "이것도 같이 고치는 게 좋습니다"라고 하면 **거절하고 기록한다**

## 4단계: 중간 점검 (15분)

```bash
git diff
```

| 점검 | 확인 |
| --- | --- |
| 계획한 파일만 바뀌었는가 | |
| 계획에 없던 변경이 있는가 | |
| 바뀐 줄 수가 예상과 비슷한가 | |
| 완료 조건을 만족했는가 | |
| `verify`가 통과하는가 | |

`PROGRESS.md`의 상태를 갱신한다.

> **완료 조건을 만족하지 못했다면 DONE으로 표시하지 않는다.**

## 산출물

- 승인자 이름이 적힌 `PROGRESS.md`
- **실패했을 때의 테스트 출력** (가장 중요)
- 수정 후 `verify` 출력
- `git diff`
