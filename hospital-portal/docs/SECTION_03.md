# 섹션 03. AI의 주장을 검증하고 계획 세우기 (55분)

> 장표 `13·33 ~ 17·33`

## 목표

고른 문제 하나에 대해 **AI의 주장을 사실·추론·추측·오류로 분류**하고, 승인받을 수 있는
수준의 계획을 만든다. 이 섹션에서도 코드를 고치지 않는다.

## 1단계: 근거 검증 (20분)

상위 `prompts/`에서 근거 검증에 해당하는 프롬프트를 사용한다.

**먼저 사람이 실행하고, 그 출력을 프롬프트에 붙여넣는다.**

```bash
./scripts/run.sh
./scripts/verify.sh
```

AI 답변을 받아 다음 표를 채운다.

| 주장 | 분류 | 근거로 인용된 줄 | 사람이 확인했는가 |
| --- | --- | --- | --- |
| | 확인된 사실 / 강한 추론 / 확인되지 않은 추측 / 잘못된 주장 | | |

### 반드시 답해야 하는 질문

> **테스트가 전부 통과하는데 왜 이 문제가 남아 있는가?**
>
> 현재 테스트가 **검사하지 않는 조건**은 무엇인가?

이 질문에 답하지 못하면 다음 단계로 가지 않는다.

### `잘못된 주장`이 나왔다면

반드시 기록한다. AI가 코드와 다른 말을 한 사례는 오늘 가장 값진 산출물이다.

## 2단계: 계획·우선순위·영향 범위 (20분)

상위 `prompts/`에서 계획·우선순위·영향 범위에 해당하는 프롬프트를 골라 **한 번에**
붙여넣는다.

받은 계획을 다음 기준으로 점검한다.

| 점검 | 확인 |
| --- | --- |
| 문제의 근거가 충분한가 | |
| 수정 범위가 과도하지 않은가 | |
| 완료 조건이 **관찰 가능한가** | |
| 검증 방법을 **내가 실제로 실행할 수 있는가** | |
| 변경하지 않을 범위가 명시되어 있는가 | |

"관찰 가능"이란 `verify` 출력이나 `run` 출력에서 **눈으로 확인할 수 있다**는 뜻이다.
"코드가 더 안전해진다" 같은 완료 조건은 관찰 가능하지 않다.

## 3단계: 계획 확정 (15분)

`docs/PROGRESS_TEMPLATE.md`를 `PROGRESS.md`로 복사하고 **사람이 직접** 채운다.
AI에게 시키지 않는다. 채팅 횟수를 아끼고, 승인의 주체를 분명히 하기 위해서다.

최소한 다음이 들어가야 한다.

```text
Task 이름
현재 상태: TODO
수정 대상 파일
변경하지 않을 범위
검증 방법 (실행할 명령)
완료 조건 (관찰 가능한 형태)
```

## 산출물

- 근거 분류 표
- "테스트가 통과하는데도 문제가 남는 이유"에 대한 답
- `PROGRESS.md` (아직 승인 전, 상태 TODO)
