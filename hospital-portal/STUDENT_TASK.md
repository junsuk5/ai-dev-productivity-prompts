# 실습 진행 방법

## 오늘 하는 일

하나의 프로젝트를 6시간 동안 **끝까지** 다룬다. 프로젝트는 바뀌지 않는다.

```text
섹션 01  나쁜 지시를 던져 보고, 그 결과를 저장한다
섹션 02  제대로 지시해서 문제 후보를 뽑고, 조별로 하나를 고른다
섹션 03  고른 문제의 근거를 확인하고 계획을 세운다
섹션 04  사람이 승인하고, 하나만 고친다
섹션 05  고친 것을 검증하고, 섹션 01의 결과와 비교한다
섹션 06  못 고친 것을 기록해서 넘기고, 반복 작업을 규칙으로 만든다
```

## 이 실습이 훈련하는 것

과정명의 `디지털 문해력`은 다음을 뜻한다.

> 디지털 도구의 결과를 그대로 받아들이지 않고, 필요한 정보를 찾고,
> 근거를 검증하고, 위험을 판단하여 목적에 맞게 활용하는 능력

| 디지털 문해력 | 오늘 훈련하는 곳 |
| --- | --- |
| 필요한 정보를 찾고 | 섹션 02 문제 발견 |
| 근거를 검증하고 | 섹션 03 근거 검증 |
| 위험을 판단하여 | 섹션 02 조별 판단 · 섹션 04 인간 승인 |
| 목적에 맞게 활용 | 섹션 05 완료 검증 · 섹션 06 인수인계 |

## 오늘의 성공 기준

> **문제를 다 고치는 것이 목표가 아니다.**
>
> 문제 하나를 근거를 갖고 고치고,
> 나머지를 다음 사람이 이어받을 수 있게 남기는 것이 목표다.

6시간이 끝났을 때 고친 문제가 **하나**여도 정상이다. 못 고친 문제가 `HANDOFF.md`에
정리되어 있다면 그것이 완료다.

### 그런데 그게 왜 생산성인가

| | 짧은 지시 | 오늘의 절차 |
| --- | --- | --- |
| 첫 결과가 나오기까지 | 빠르다 | 느리다 |
| 검증 | 없다 | 있다 |
| 운영에 반영한 뒤 | 재작업 | 없음 |
| 되돌려야 할 변경 | 많다 | 없다 |
| 다음 담당자 | 처음부터 다시 | `HANDOFF.md`로 이어받는다 |

> **AI로 빨라지는 것은 생성이지 완료가 아니다.**
>
> 다시 하지 않는 것이 생산성이다.

오늘 채팅을 10회 안팎만 쓰는 것도 같은 이유다. 많이 물어보는 것이 아니라
**적게 물어보고 한 번에 끝내는 것**이 목표다.

## 시작하기 전에

1. `README.md`를 읽는다
2. 상위 폴더의 `prompts/`를 열어 둔다. 이 프로젝트 전용 프롬프트는 없다 —
   각 섹션에 맞는 프롬프트를 그 폴더에서 직접 골라 쓴다
3. `docs/RESULT_TEMPLATE.md`를 `RESULT.md`로 복사한다
4. 터미널에서 기준점을 확인한다

```bash
./scripts/run.sh
./scripts/verify.sh
```

두 출력을 `RESULT.md`에 붙여넣는다. **이것이 오늘의 시작 상태다.**

## 시간표

| 시각 | 섹션 | 내용 | 시간 |
| --- | --- | --- | ---: |
| 10:00 | 01 | 먼저 실패해 보고 프롬프트 해부하기 | 45분 |
| 10:45 | 02 | 프로젝트를 이해하고 문제 발견하기 | 45분 |
| 11:30 | 03 | AI의 주장을 검증하고 계획 세우기 | 55분 |
| 12:25 | | 점심 | 60분 |
| 13:25 | 04 | 인간이 승인하고 작은 단위로 구현하기 | 60분 |
| 14:35 | 05 | "완료했습니다"를 검증하기 | 50분 |
| 15:35 | 06 | 상태를 보존하고 반복 작업을 시스템화하기 | 45분 |

실습 합계 **300분**. 섹션 04와 05 사이, 05와 06 사이에 휴식 10분이 있다.

각 섹션에서 어떤 프롬프트를 쓸지는 정해져 있지 않다. `prompts/` 폴더를 보고 그 섹션의
목적에 맞는 걸 직접 고른다. 여러 개가 필요해 보이면 **나눠서 묻지 말고 한 번에 정리해서
묻는다** — 이것도 오늘 훈련하는 것 중 하나다.

## 공통 규칙

- 분석 단계에서는 코드를 수정하지 않는다
- 문제 후보는 최대 3개로 제한한다
- **반드시 하나 이상의 제안을 거절한다**
- 수정 실습은 **테스트 실패를 먼저 눈으로 확인**한 뒤 시작한다
- AI의 완료 보고가 아니라 `verify` 출력, `git diff`, 사람 판정으로 끝낸다
- 한 섹션 안에서 프롬프트를 여러 번 나눠 던지지 않는다
- 환경 문제로 3분 이상 막히면 강사에게 알리고 다음으로 넘어간다

## 완료 증거

AI 답변은 완료 근거가 아니다. 다음 여섯 가지로 판정한다.

```text
코드에서 확인한 근거
승인하거나 거절한 이유
변경 전후 diff
verify 출력 (JUnit + 컴파일 경고)
HANDOFF.md
사람의 최종 판정과 승인자 이름
```
